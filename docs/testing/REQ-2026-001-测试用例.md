# REQ-2026-001 AI 研发流水线 — 测试用例（AC-1~12）

> 用例编号 TC-xx 对应 AC-xx。`E=`环境（接口断言=后端 API，界面断言=浏览器 9000 端口页面）。

## TC-1（AC-1）新建需求：标题必填、编号唯一

| 项 | 内容 |
|---|---|
| 前置 | 已登录且拥有 `pipeline:edit` 权限 |
| 步骤 | ① 调用 `POST /api/v1/pipeline/requirements`，body 仅 title，其余字段省略 → 期望 200，返回 `req_no` 形如 `REQ-2026-XXX` 且唯一；② body 缺 title → 期望 400；③ body title 全空格 → 期望 400；④ 连续创建 2 条 → req_no 递增不重复 |
| 预期 | 编号自动生成、数据库唯一索引兜底、标题必填 |
| 结果 | **PARTIAL（静态 PASS / 动态待环境）** |
| 证据 | 静态：handler `CreateRequirement` 对 `Title` 做 `binding:"required"`+TrimSpace 校验；表 `req_no TEXT NOT NULL UNIQUE`；编号由 `nextReqNo` 查询 MAX 自增。动态执行需部署环境 |

| 项 | 内容 |
|---|---|

| 步骤 | ① 仅 status=backlog → 只返回 backlog 且 count 正确；② status+kano_category+priority 组合 → 交集正确；③ keyword=标题关键字 → 命中正确；④ page=2&page_size=3 → 返回第 2 页 3 条，total 正确；⑤ aarrr=activation → 返回含 activation 需求 |
| 预期 | 各筛选独立正确、组合取交集、分页 total 准确 |

## TC-3（AC-3）状态流转：状态机校验

| 项 | 内容 |
|---|---|
| 前置 | 存在 draft 需求一条 |
| 步骤 | ① 合法链依次流转 draft→backlog→prd→dev→test→verify→review→done，每次 200 且 status 更新；② 非法流转 draft→prd、dev→review、done→backlog 等 → 400；③ review 阶段执行 done → 200 |
| 预期 | 合法转移放行，非法转移拒绝（400），`review→done` 合法 |
| 结果 | **PASS（单测 31 例全部通过）** |
| 证据 | `go test ./internal/handlers -run TestStatusTransitions`：18 例合法 + 13 例非法全 PASS |

## TC-4（AC-4）删除限制：进入 PRD 后禁止删除

| 项 | 内容 |
|---|---|
| 前置 | 有 draft 与 dev 需求各一条 |
| 步骤 | ① `DELETE /api/v1/pipeline/requirements/:id` 删 draft → 200；② 删 dev 状态需求 → 期望 **409** |
| 预期 | draft/backlog 可删除；已进入 PRD 及之后状态返回 409 |
| 结果 | **PARTIAL（语义正确 / 状态码偏差，见缺陷 D2）** |
| 证据 | 静态：`DeleteRequirement` 对非 draft/backlog 返回 400（应为 409）；draft/backlog 可删逻辑正确 |

## TC-7（AC-7）权限：无 review 权限不可审核

| 项 | 内容 |
|---|---|
| 前置 | 存在无 `pipeline:review` 权限的角色用户 |
| 步骤 | ① 该用户调用 `POST /api/v1/pipeline/requirements/:id/reviews` → 期望 **403** |
| 预期 | 无 `pipeline:review` 权限返回 403 |
| 结果 | **FAIL（见缺陷 D1）** |
| 证据 | 静态：`pipeline` 路由组未挂 `RequirePermission("pipeline:review")`，`CreateReview` 仅校验登录，任何登录用户可审核 |

## TC-8（AC-8）打回：必带环节与原因

| 项 | 内容 |
|---|---|
| 前置 | 需求处于 verify 状态 |
| 步骤 | ① 打回 action=reject 且 target_stage=F、reason=空 → 期望 **400**；② target_stage 非法值（如 X）→ 期望 400；③ 合法打回（F + 原因）→ 200 且状态变 rework、F 环节 doing、G 置 todo；④ 打回后经 rework 重新流转到 review 允许 |
| 预期 | 环节与原因均必填；打回置 rework 且目标环节及其后全部重置 |
| 结果 | **PARTIAL（环节校验 PASS / 原因未校验，见缺陷 D3）** |
| 证据 | 静态：`CreateReview` 仅校验 `target_stage`（A~G）合法性，`reason` 为空不拦截；打回重置逻辑单测 `TestRejectStageReset` PASS |
