# 原始需求 · REQ-2026-001 提案

> 状态：待评估（员工A）｜ 来源：老板 2026-08-12

## 一句话需求
在 AI 起爆一体化工具集内新增 **「AI 研发流水线可视化后台」** 模块，用网页界面管理多AI员工（需求分析师→产品经理→前端/后端/嵌入式→测试→验证）的需求流转、进度看板与审核操作，替代纯对话式驱动。

## 背景与痛点
- 目前多AI员工流水线靠 CodeBuddy 对话驱动，需求状态、交付物、进度不直观；
- 老板需要一个**统一的审核界面**（通过/打回），而非在对话里确认；
- 需求池、PRD、测试报告散落在 docs 文件里，缺乏集中查看入口。

## 期望功能（初步，待员工B细化）
1. **需求池管理**：需求录入/编辑、卡诺分类标签（M/O/A/I/R）、AARRR 关联标签、优先级 P0/P1/P2、状态流转
2. **流水线看板**：每个需求走到哪个员工环节（A~G 状态灯），进度一目了然
3. **交付物管理**：PRD / 原型 / 测试报告 / 审核汇总 在线预览
4. **审核区**：老板对每个需求 ✅通过 / ⛔打回（带环节与原因）
5. **统计报表**（二期可选）：需求全流程耗时、各环节处理时长

## 技术栈约束
- 前端：Vue3 + Element Plus（现有 src/ 规范）
- 后端：Go 1.21 + Gin + PostgreSQL（现有 backend/ 规范，自动迁移建表）
- 鉴权：沿用现有 JWT + 权限码（老板角色才有审核权限）
- AI 能力：首期不接大模型 API；二期可接入自动生成 PRD/测试用例

## 约束与风险
- 不修改现有登录链路（sys_user 方案）与用户管理接口（user_profiles）
- 新模块路由挂 /ai-pipeline，不影响现有功能
- 若二期接 AI 生成，需评估大模型 API 成本与数据安全（涉密日志不可外发）
